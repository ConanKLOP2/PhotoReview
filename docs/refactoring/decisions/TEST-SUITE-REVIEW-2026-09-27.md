# TEST-SUITE-REVIEW-2026-09-27 — external multi-agent test-suite review

External static, read-only multi-agent review of the whole test suite surfaced 9 findings. Each was
independently re-verified against the current source before any change (never trusted the review's
prose alone).

| # | Verdict | Evidence | What changed |
|---|---|---|---|
| 1 | confirmed-fixed | `SourceBytesCacheRobustnessTests.EvictBetweenCheckAndSet_DoesNotRepublish` had no timeouts on `paused.Wait()`/`reader.Join()`/`evictor.Join()`, ignored `SpinWait.SpinUntil`'s bool result, and had no `try/finally` around `release.Set()`. Mutation-check: removing the `_publishGate` lock/version-check in `SourceBytesCache.ReadAndCache` now makes the test fail (`Assert.Equal` 0 vs 1) instead of hanging. | Added a 10 s timeout + failure message to every `Wait`/`Join`, asserted `SpinWait.SpinUntil`'s return value, wrapped the body in `try/finally` so `release.Set()` always runs. Same race still exercised. |
| 2 | confirmed-fixed | `FileLogLifecycleTests.DisposeUnderLoad_WritersNeverThrow` used `Thread.Sleep(round % 5)` (0-4 ms) before `Dispose()`, a fixed, machine-dependent delay banned by AGENTS.md "Tests" rule, with no guarantee it lands inside the writers' active window. | Replaced the sleep with `SpinWait.SpinUntil(() => log.PendingCount > queuedThreshold || ..., 10s)`, using the existing internal `FileLog.PendingCount` test seam so each round deterministically waits for real evidence that writers have queued work (threshold scales with `round`) before racing `Dispose()` against them. |
| 3 | confirmed-fixed | `AssertOnDiskIsPerThreadPrefix` returned immediately when `dropped != 0`, skipping the duplicate/order/gap checks for every round that actually exercises the overflow-drop path (5 of 6 rounds, once round varies queue pressure). Mutation-check: making `FileLog.Drain` write every entry twice now fails the helper ("reordered or duplicated retained entry") instead of passing silently. | Helper now always checks each thread's retained sequence is strictly increasing (no reorder/dup) regardless of drops; when `dropped == 0` it still requires the full contiguous prefix; when `dropped != 0` it additionally bounds the missing-below-max-index count by the total dropped count. |
| 4 | confirmed-fixed | `DecoderContractRegressionTests.TurboHeaderFailureAttemptsWpfFallbackExactlyOnceAndPreservesFinalException` used `Assert.ThrowsAny<Exception>`, which cannot tell "the fallback's own exception propagated unwrapped" (the real contract in `FallbackImageDecoder.Decode`) apart from "the primary's exception leaked" or "some other exception happened". Mutation-check: wrapping the fallback's exception path to rethrow the *primary's* exception instead now fails the test (`FileFormatException` expected, `InvalidDataException` — the primary's actual TurboJPEG failure — was thrown). | Fallback (`CountingDecoder(new ThrowingDecoder(sentinel))`) now throws a distinct sentinel `FileFormatException`; test asserts `Assert.Throws<FileFormatException>` and `Assert.Same(sentinel, thrown)`. |
| 5 | confirmed-fixed | `DecoderQualityGateTests.CorruptFilesFailSafelyWithoutCrash` used `Assert.ThrowsAny<Exception>` for 3 of 4 corrupt-input cases (empty file, text-as-jpeg, truncated header) despite an inline comment saying "must throw typed exception" — would silently accept a leaking `NullReferenceException`/`InvalidCastException`/etc. Investigation (subagent read of all 3 decoders' actual exception surfaces) found `WicDirectDecoder` throws a raw, unwrapped `COMException` for all 3 cases (its `IWICImagingFactory.CreateDecoderFromStream`/`GetFrame` calls are not `[PreserveSig]`), which the existing 4th-case union (`InvalidDataException`/`FileFormatException`/`NotSupportedException`/`IOException`) does not cover. Mutation-check: a decoder that throws `InvalidCastException` now fails the shared helper. | Added `AssertTypedDecoderFailure` helper reusing the exact type set already established for this input class by `DecoderFileEdgeCaseTests.IsUnderstood` (adds `COMException`, `UnauthorizedAccessException` to the 4-type union); the 3 weak cases now use it. The 4th case (half-truncated scan, which also allows a successful decode) is unchanged. |
| 6 | rejected-false-positive | Review claimed `WpfPresentationSinkTests` (`[Trait("Category","UI")]`) is missing `[Collection("GlobalState")]`. Its private `DispatcherThread` helper only calls `Dispatcher.CurrentDispatcher`/`Dispatcher.Run()` on its own dedicated STA thread — never touches `System.Windows.Application`/`Application.Current`. Verified every one of the 67 files using `[Collection("GlobalState")]` in the repo: the collection is a general "any process-wide mutable global" bucket (env vars like `PHOTOREVIEW_PERF_TRACE`/diagnostics flags, the ambient static `Localizer`, `FileLog.Default`, and — for `CompositionRootTests`/`DarkScrollBarRenderingTests` specifically — `System.Windows.Application.Current`/`new Application(...)`), not exclusively an "Application singleton" rule. `WpfPresentationSinkTests` touches none of these: its dispatcher, `ReviewMetrics`, and sink are all freshly constructed, unshared instances. No real shared-state hazard found. | No change. |
| 7 | confirmed-fixed | `PerfTraceTests.ListenerDoesNotBlockUnderBurstAndAccountsForEveryEvent` asserted `sw.Elapsed < TimeSpan.FromSeconds(5)` after emitting 200k events — an absolute wall-clock threshold already observed to fail once under heavy CI/full-suite load (`docs/refactoring/decisions/FLAKY-FolderLoad.md` line 58: 7.3 s in a 9-minute full-suite run). | Split into `ListenerAccountsForEveryEventUnderBurst` (no wall-clock assertion; keeps `Assert.Equal(total, dataLines + dropped)` as the real oracle) and `ListenerDoesNotBlockProducerUnderBurst` (keeps the same 5 s check, now tagged `[Trait("Category","Slow")]` so it is excluded from the default gate `Category!=Manual&Category!=Native&Category!=Slow`, per the review's "prefer dropping or tagging Slow" option). Mutation-check: the dedicated `PerfCsvListenerDropTests.DroppedRowsAreCountedAndReported` (existing test covering the same drop-counting mechanism) fails when the channel's `itemDropped` callback is neutered, confirming the accounting oracle is real. |
| 8 | rejected (already-sanctioned) | `NativeRecycleBinTests`: AGENTS.md already states "Native bin tests only remove their own items" as repo policy. Not a new problem; not an action item. | No change (per instructions, not touched). |
| 9 | confirmed-gap, documented (not fixed) | `FileHashServiceCancelTests`: all 3 cancellation tests call `cts.Cancel()` immediately after (or even before) `GetAsync`, so none prove cancellation lands mid-read (I/O actually in flight) vs. before the read starts. Read `FileHashService`: it has no read-progress test seam (unlike `SourceBytesCache`'s `BeforePublishForTests`/`AfterReadForTests` or `FileLog`'s `DrainHook`), and the actual read goes through either `SourceBytesCache.GetOrRead` (synchronous, no seam either) or a raw `SHA256.HashDataAsync(stream, cancellationToken)` call with no per-chunk hook. Adding a production seam for this would mean either instrumenting `SHA256.HashDataAsync`'s call site or wrapping the `FileStream` in a byte-counting decorator solely for tests — both are more invasive than this pass's scope, and a sleep-based "prove mid-read" test would violate the no-fixed-delay rule. | No production seam added this pass; left as a documented coverage gap rather than fabricating a racy/unbounded test. The 3 existing tests (pre-canceled, cancel-sole-caller, cancel-one-of-two) still validate real, useful contracts (just not the mid-read timing specifically). |
