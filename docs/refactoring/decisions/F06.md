# F06 - backup before the settings repair write-back

## Current state

When `SettingsStore` loads values it has to repair (out-of-range or invalid fields), it rewrites config.json with the repaired values
and the old values are gone. The salvage path (unparseable file) already keeps a backup of the original before replacing it.

## Options

| | Change | Pros | Cons |
|---|---|---|---|
| A | Leave | No change | The original values are lost; a bad repair (or a value a newer version wrote) cannot be recovered |
| B | Back up before any repair write-back | Same safety as the salvage path; small | One more file next to config.json; needs a policy for repeated repairs (overwrite or numbered) |
| C | Show the old values in the start-up dialog | User sees what changed | No recovery if the user does not copy them; dialog text and localization |

## Decision

Option B, chosen by the user on 2026-10-06. Code: separate PR on branch `fix/settings-repair-backup`.

## When to revisit

If the backup file accumulates or confuses users: reconsider C as the user-facing report.
